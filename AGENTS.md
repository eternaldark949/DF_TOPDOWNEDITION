# Working in ETRNLNINE

Read README.md and the applicable docs/decisions records (First Light, Between Worlds, Profiler, Ambient Occlusion, Lighting/Shadows, Studio/3D/Authored Data, and First Studio Workspace) before changing source. The owner's house architecture and commenting requirements govern this branch.

- Basement defines reusable mechanisms; Lobby alone owns runtime scheduling; Directory manages registered libraries/worlds/resource ownership; Penthouse supplies reusable toys. ETRNLNINE remains a small composition root.
- Game/example rules and content stay outside engine/. Engine code never imports them or looks up game DOM IDs.
- No Canvas 2D rendering or asset/text preparation, runtime frameworks, CDN requirements, competing animation-frame loops, hidden game globals, prototype patches, or alternate renderer bypasses.
- Comment files, classes, functions, shaders, configuration, meaningful blocks, ownership, units, lifecycles, and editing points generously. Keep explanations accurate as code changes.
- Move misplaced responsibilities to their appropriate home in the same coherent change. No god objects, bandaid classes, or bolted-on exceptions; a wrapper is not a repaired boundary.
- Every instance owns mutable state, registrations, and cleanup. Shared resources require explicit leases. Repeated create/dispose and pause/focus changes must remain safe.
- Keep adopted decisions, implementation status, and open proposals distinct. Do not claim planned systems or scaffolds are implemented.
- Run npm test and npm run build after relevant source changes. Use npm run test:browser for rendering/input/lifecycle changes when Playwright/Chromium are available; see the decision guide for setup and environmental limitations.
- Commit the rebuilt dist HTML with source changes. Record real verification results and limitations; emulated mobile and software WebGL do not prove physical-device performance.

For world work, preserve active/preparation ownership and final-boundary validation. Readiness promises resolve without resource values; use the owned ticket.value. Never move actor membership from an asynchronous completion or retain borrowed world resources after releasing their ticket.

For profiling, register static bounded names once and close synchronous scopes in finally. Do not poll or wait for GPU completion in hot paths. Own provider/view subscriptions, distinguish CPU/interval/GPU measurements, and label buffer sizes and capture-time versus historical data accurately.

For AO, read docs/decisions/0004-ambient-occlusion.md. Preserve ambient-only attenuation, bounded candidate/target budgets and the original antialiased forward path. Screen-space AO is SSAO, not GTAO or cast shadows. Keep texture-storage estimates distinct from requested buffer bytes. Free optional targets/programs on quality disable, and preserve context restoration and geometry fallback.

For lighting, read docs/decisions/0005-lighting-and-shadows.md. Light data belongs to renderer.lighting; do not reintroduce renderer-field aliases. Camera-visible geometry is not the shadow caster list. Preserve the one-sun/one-point budget, material-independent depth cache, plane-correct comparisons, immediate source-batch cleanup and complete six-face cube updates. Keep estimated texture bytes separate from requested buffers.

Before authoring/editor/scene-format/build work, read docs/decisions/0006-studio-3d-and-authored-data.md and docs/decisions/0007-studio-first-workspace.md. The engine targets full 3D with game-chosen presentation. Studio uses one contextual workspace, shared properties/commands and the existing scheduler. Authored JSON is the source of truth; JavaScript implements behavior. Validate and embed explicit project dependencies into offline HTML without eager world/GPU construction. The first Studio/JSON/build workflow is implemented; preserve the explicit limits in decision 0007 and examples/atrium/DOCUMENTS.md. Run npm run test:studio for editor lifecycle/input/file changes. Keep editor/ and game data outside engine/; preserve house ownership, stable authored IDs, touch cancellation and edit/play isolation.

For authoring guides and placement commands, also read docs/decisions/0008-studio-authoring-tools.md. Preserve renderer-owned guide resources, separate view preferences, monotonic authored IDs, unaffected runtime identities, transactional gestures and injected application policies. Run npm run test:studio-tools for these changes in addition to the applicable existing suites.

For Freelancer/world-content work, read docs/decisions/0009-freelancer-street-slice.md and games/freelancer/DOCUMENTS.md. Source JSON remains authoritative; do not run the explicit authoring recipe over user edits during normal builds. Keep named game metadata/policies outside engine/. Doorway commits recheck source reach and destination legality. Run npm run test:freelancer for this gameplay/editor integration.

For viewport navigation, read docs/decisions/0010-viewport-navigation.md. Preserve separate camera/document state, pointer ownership, deferred touch placement, second-finger transform rollback and the single Lobby subscription. Run npm run test:camera plus applicable editor regressions. Do not claim perspective or expanded light-object parameters from this milestone.

For perspective, read docs/decisions/0011-perspective-camera.md. Both lenses share camera, navigation, culling, picking, AO and guide contracts. Preserve homogeneous depth reconstruction, depth-aware screen sizing, camera-independent shadow casters and complete edit/Play pose restoration. Run npm run test:perspective for lens/authoring/rendering checks in addition to existing camera/editor/runtime regressions. For the subsequent HDR bloom implementation and remaining clustered-lighting roadmap, follow decision 0012 below.

For HDR bloom, read docs/decisions/0012-hdr-bloom.md. Preserve linear radiance before composition/encoding, MSAA capability fallback, guide rendering after post with resolved depth, bounded target ownership and failure latching. Keep target estimates separate from buffer bytes and CPU submission time separate from GPU time. Studio and Freelancer share the parameterized Penthouse widget; appearance settings do not dirty project JSON. Run npm run test:bloom and relevant runtime/editor/game regressions. Bloom is now implemented; scalable clustered lighting remains next.

For presentation/material work, read docs/decisions/0013-presentation-and-materials.md. Presentation owns HDR scene/depth/MSAA, exposure and composition; Bloom owns only its filter. AppearanceControls is the shared UI. The material milestone introduced schema version 2 with linked material IDs (decision 0019 advances canonical objects to v3) and placement overrides; legacy v1 migrates once at ingress. Runtime material copies are scene-owned and shared within each scene; authored data is never mutable runtime storage. Emission colour/strength are standard material properties, not light objects. The initial lit records were 20 floats; decision 0018 extends them to 24. Shadow records remain 16. Run npm run test:materials plus relevant bloom/runtime/Studio/tools/Freelancer regressions.

For bloom art direction, read docs/decisions/0014-bloom-art-direction.md. BLOOM_PARAMETERS is the common validation/UI catalog. Preserve recipe/exposure independence, derived Custom state, bounded storage and zero-haze/default appearance. Haze reuses the smallest reduction, adds reads only on the final reconstruction, and is not volumetric fog. Run npm run test:bloom and applicable rendering/editor regressions.

For Studio shell/panel work, read docs/decisions/0015-studio-diamond-shell.md. PanelDock owns accessible view state and media listeners; the application owns layout and gesture/document policies. Use shared Penthouse theme/dock CSS and the one editor stylesheet. Do not reintroduce parallel mobile toggles/body visibility flags. Preserve labelled 44px controls, inert hidden panels, layout/Play restoration, and offline stylesheet embedding. Run test:studio-shell and relevant Studio/tools/camera/appearance regressions.

For Viewport/iconography work, read docs/decisions/0016-viewport-panel-and-iconography.md. Keep shortcut/detail state unified, responsive nodes reachable, icon-only names accessible, and native section navigation independent of project history. Run test:viewport-ui plus applicable shell/Studio/tools/camera/appearance regressions.

For toolbar folding, read docs/decisions/0017-studio-tool-surface.md. Tools use a second PanelDock on the stage, with a disjoint root and independent layout choices. Preserve the active mode, unchanged canvas, keyboard focus, drawer/placement independence and both Play restoration states. Run test:tool-fold plus applicable shell/tools/camera checks.

For surface/colour work, read docs/decisions/0018-surface-response-and-colour.md. Optional v2 specular fields default at runtime/inspector without mutating old JSON. Lit records are now 24 floats/96 bytes; shadow records stay 16/64. Preserve direct-light GGX response, parallel orthographic view rays, zero-reflectivity legacy output and material-independent shadow caching. Shared ColorControl owns CSS wheel/modal/listeners; PropertyInspector owns the one dialog transaction. Keep linear authored RGB distinct from sRGB wheel/hex and HDR gain; retain exact unchanged values, cancellation, modal shortcut isolation and owned cleanup. Run test:surface, test:materials and applicable renderer/bloom/Studio regressions.

For objects/numeric controls, read docs/decisions/0019-origins-locks-and-number-surfaces.md. Canonical schema is now v3: nullable geometry asset and parent-before-child object links; v1/v2 upgrade at ingress. Stable runtime origins own replaceable geometry branches. Preserve local/world conversion, reparenting identity/poses, descendant bounds, independent visibility/selectability/locks, inherited-lock ownership and protected descendant deletion. Shared geometry references and unique copies keep materials separate. NumberControl/TextControl own input sessions; PropertyInspector composes lifetimes. Range keyboard steps must not commit before Escape/blur; color-modal Escape cancels the outer transaction. Run test:objects and applicable runtime/Studio/tools/camera/viewport/material/surface/bloom/Freelancer checks. General mesh modeling and parented light components remain future work.

Bodies are box segments: do not describe them as meshes, skinning or IK. The street slice keeps the diagnostic traveler until the owner approves the proportions. Run npm test and npm run test:humanoid.
